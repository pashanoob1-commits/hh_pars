# Резюме по референсам

## 1. HollowWonder/hh-job-tracker (эталон архитектуры парсера)

**Что берём:**
- Работа только через официальный API `api.hh.ru` (httpx) — без HTML-скрапинга
- Нормализованная SQLite-база: разделение на «обзор» вакансии (поля списка) и «детали» (snippet, режим зарплаты); таблица `currencies` для курсов
- Pydantic/TypedDict-модели вакансий вместо сырых dict
- Разделение слоёв: парсер (API) / БД / фильтры / интерфейс
- Структурное логирование с ротацией файла

**Что делаем иначе и почему:**
- Референс использует `fake_useragent` (случайный User-Agent) — это **нарушение требований hh.ru** и путь к блокировке. Мы используем честный идентифицируемый UA из конфига (`hh-parser-bot/1.0 (email)`).
- Синхронный httpx → **async httpx.AsyncClient** с rate limiting и retry с экспоненциальной задержкой (429/5xx), т.к. у нас фоновый планировщик и неблокирующий бот.
- Hardcoded-конфиг в `config.py` (dict в коде) → **pydantic-settings + .env**.
- Плоская пагинация «все 20 страниц» → для мониторинга новых вакансий достаточно первой страницы с `order_by=publication_time` + дедупликация; пагинация оставлена опционально.
- pandas для фильтрации → избыточен для бота, фильтруем на уровне SQL и параметров API-запроса.

## 2. osiriser/hh.ru_parser_telegram_bot (обёртка в бота)

**Что берём:**
- Идею управления процессом через чат (aiogram) и inline-кнопки
- Docker-развёртывание как вариант запуска
- Экспорт результатов в CSV

**Что делаем иначе и почему:**
- Референс скрапит HTML через **Selenium + BeautifulSoup** — это именно та известная проблема потери ~60% вакансий и хрупкости к изменениям вёрстки. Мы используем только API.
- aiogram 2.x → **aiogram 3.x** (актуальная версия, другой API диспетчера, FSM встроен).
- Один общий CSV для всех → мультипользовательская БД с изоляцией по `telegram_id`, персональные подписки и дедупликация.
- Токен в `ENV` Dockerfile → **.env + .env.example**, токены не в коде и не в образе.
- Запуск парсинга по кнопке → фоновый **планировщик (APScheduler)** с интервалом из конфига.
