# hh-parser-bot: мультипользовательский Telegram-бот мониторинга вакансий hh.ru

## Задача

Разработай с нуля мультипользовательский Telegram-бот для мониторинга вакансий hh.ru и положи его в этот репозиторий (предложи структуру, если репозиторий пустой — создай папку hh-parser-bot). Каждый пользователь бота настраивает свои поисковые подписки и получает уведомления о новых вакансиях.

## Контекст и референсы

Перед стартом изучи два проекта-референса на GitHub (прочитай их README и ключевой код через gh api или web fetch) и переиспользуй их сильные идеи:

1. HollowWonder/hh-job-tracker — эталонная архитектура парсера: работа через официальный API hh.ru (api.hh.ru, docs: dev.hh.ru) без HTML-скрапинга, нормализованная SQLite-база, конвертация зарплат в одну валюту, фильтрация (опыт, зарплата, график, регион), CLI.
2. osiriser/hh.ru_parser_telegram_bot — пример обёртки парсера в Telegram-бота с управлением процессом через чат.

Важное требование: только официальный API hh.ru, никакого парсинга HTML (известная проблема: HTML-парсеры теряют до ~60% вакансий со страницы поиска).

## Функциональные требования (MVP)

### Мультипользовательность
- Каждый пользователь регистрируется в боте командой /start (запись в БД, изоляция данных по telegram_id).
- У каждого пользователя — свои подписки на поиск (несколько штук), своя история полученных вакансий.

### Подписки на поиск
- Создание подписки через диалог в боте: поисковый запрос (текст), регион (выбор из списка популярных + поиск по названию через API /areas), опыт, занятость, вилка зарплаты (мин/макс), только с указанной зарплатой (да/нет).
- Команды: /add (мастер создания), /list (мои подписки), /del <id> (удалить), /pause и /resume (приостановить/возобновить).
- Лимит подписок на пользователя (например, 10) — защита от злоупотреблений.

### Планировщик и уведомления
- Фоновый планировщик (APScheduler или asyncio-loop) опрашивает API hh.ru по всем активным подпискам каждые N минут (конфигурируемо, по умолчанию 15).
- Дедупликация: вакансия приходит пользователю только один раз (таблица sent_vacancies: user_id + vacancy_id).
- Сортировка выдачи по дате публикации (order_by=publication_time), получение только новых с прошлой проверки.
- Формат уведомления: название, компания, зарплата (нормализованная, в одной валюте), регион, ключевые требования (snippet), ссылка. Кнопки: «🔥 Откликнуться» (ссылка), «⭐ В избранное», «🚫 Скрыть компанию» (чёрный список).

### Аналитика (вторая очередь, заложи архитектуру)
- /stats — статистика по подписке: медианная зарплата, топ-10 навыков (key_skills), динамика числа вакансий.
- Экспорт выборки в CSV.

## Технические требования

- Стек: Python 3.11+, aiogram 3.x (бот), httpx (async-клиент к API), SQLite через aiosqlite или SQLAlchemy (БД должна легко меняться на PostgreSQL — не прошивай диалект), APScheduler, pydantic для конфига и моделей.
- Конфигурация через .env (BOT_TOKEN, HH_USER_AGENT, интервал опроса и т.д.) + .env.example в репозитории.
- User-Agent для API hh.ru обязателен (требование hh): hh-parser-bot/1.0 (email).
- Уважай rate limits API: минимальный интервал между запросами, retry с экспоненциальной задержкой на 429/5xx, обработка 403.
- Конвертация зарплат: курсы из /dictionaries API hh (или ЦБ), кешируй на сутки.
- Структура БД: таблицы users, subscriptions, sent_vacancies, favorite_vacancies, blocked_employers. Миграции — простым SQL-скриптом или alembic.
- Логирование: структурное, ротация файла, уровень из конфига.
- Запуск: docker-compose.yml (бот + volume для SQLite) И возможность запуска без Docker (python -m bot).
- Тесты: юнит-тесты на парсер API (с замоканным httpx), дедупликацию, конвертацию валют, команды бота (хотя бы базовые).
- README.md: установка, получение токена бота у @BotFather, настройка .env, запуск (обычный и Docker), скриншоты/примеры команд, дорожная карта.

## Порядок работы

1. Сначала изучи референсы и напиши краткое резюме: какие идеи берём, что делаем иначе и почему.
2. Покажи схему БД и список команд бота — дождись подтверждения или правок.
3. Реализуй ядро: HH API клиент + БД + дедупликацию, покрой тестами.
4. Затем бот (хендлеры, мастер подписки), затем планировщик.
5. После каждого осмысленного этапа коммить с понятным сообщением и пушь в отдельную ветку (не в main). Не храни токены в коде.
6. В конце: прогони тесты, заполни README, сделай пример .env, проверь docker compose config.

## Критерии готовности MVP

- Бот стартует, пользователь проходит /start
- Создание подписки через диалог с выбором региона из API
- Планировщик присылает только НОВЫЕ вакансии (дедупликация работает)
- Зарплаты показываются в одной валюте
- Чёрный список компаний работает
- Тесты зелёные, README полный, docker-compose поднимает бота одной командой

## Вне скоупа MVP (не делать, только заложить расширяемость)

- Автоотклики на вакансии (риск бана аккаунта hh, отдельная тема)
- Веб-панель администратора
- Платные подписки/монетизация
